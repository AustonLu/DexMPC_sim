# dexmpc-sim v0.3.0 高层 Operator SDK：设计、安装与 Kernel 开发手册

适用版本：`dexmpc-sim 0.3.0`  
适用分支：`DexMPC_sim/compiler`  
目标平台：Linux x86-64  
硬件后端：TopChip D2D cycle-accurate Verilator simulator，command context/core0

## 1. v0.3.0 解决什么问题

v0.2 已经提供 persistent `Session`、全部单核基本算子的 command builder 和 bit-exact 验证，但调用者仍需了解 Global/Local/Temp SRAM、word offset 和 command ID。

v0.3.0 在其上提供无地址的高层 Tensor/Operator API。普通软件开发者只需要：

```python
import dexsim

with dexsim.Device() as dev:
    a = dev.tensor([[1.0, 2.0], [3.0, 4.0]])
    b = dev.tensor([[5.0, 6.0], [7.0, 8.0]])
    c = dev.gemm(a, b)
    print(c.numpy())
```

调用者不需要指定：

```text
Global/Local/Temp SRAM
mem_id / word_offset
command_id
opcode / subop
group_end
core / context
LUT 初始化
输入输出物理地址
```

包内部自动完成 FP16 量化、数据打包、SRAM placement、生命周期、command 编码、Simulator 执行和结果读取。

## 2. 设计原则和旧 stack 复用

v0.3.0 没有重新开发第二套底层后端。它复用了两组已经存在的成果：

### 2.1 旧 `compiler-stack-dev` 的高层抽象

迁移来源：

```text
6494cc4  VariableRef / VariableAllocator / InstructionBuilder
3460499  free-list 生命周期复用
32d7eb4  OperatorTensor / OperatorRuntime
8e5f1ca  Python Device/Tensor interface
```

保留的设计包括：

- Tensor handle；
- 按 memory 独立的 word-aligned allocator；
- high-water 分配和 free-list 复用；
- Tensor release 和 stale handle 检查；
- 自动输出分配；
- 高层算子 shape 检查；
- persistent device/runtime。

### 2.2 当前 v0.2 的已验证执行后端

v0.3.0 不复制旧 stack 的 command bit encoder 和旧 simulator backend，而是统一使用当前：

```text
python/dexsim/commands.py
python/dexsim/session.py
runtime C ABI
TopChip Verilator model
```

因此继承了 M2.1 已确认的：

- 全 tensor SRAM 越界和 alias 检查；
- SCALE scalar bit 编码；
- ASSEMBLE 目标 shape 语义；
- Sin/Cos/Softplus LUT 懒加载；
- Reduce 逐 command result 和 tie 规则；
- ADD 的 FTZ/signed-zero 行为；
- timeout、illegal command 和完成元数据检查。

## 3. 软件层级

```text
MPC/Kernel Python code
        |
Device / Tensor / Program             v0.3 public API
        |
VariableAllocator / OperatorRuntime   automatic placement/lifetime
        |
verified command builders             96-bit encoding
        |
persistent Session / C ABI
        |
TopChip Verilator model               FP16 hardware execution
```

生产代码应使用 `Device`、`Tensor` 和可选 `Program`。低层 `Session` 和 command builder 继续保留，用于硬件验证、golden command 和故障定位。

## 5. Device 和 Tensor

### 5.1 创建运行设备

```python
import dexsim

dev = dexsim.Device()
```

推荐用 context manager：

```python
with dexsim.Device() as dev:
    ...
```

一个 `Device` 对应一个 persistent `Session` 和一次 TopChip model reset。重复算子调用不会反复重建 simulator。

### 5.2 创建普通 Tensor

```python
x = dev.tensor([1.0, 2.0, 3.0])
A = dev.tensor([[1.0, 0.0], [0.0, 1.0]])
```

输入在上传前转换为 IEEE FP16。当前高层硬件 Tensor 支持一维或二维非空 shape。

### 5.3 创建驻留常量

```python
Q_inv = dev.constant(q_inv_numpy)
```

只要 `Q_inv` handle 保持 live，它的 FP16 数据就驻留在当前 Device 中，可以跨多个 kernel/迭代复用，不需要每次重新上传。

### 5.4 读取结果

```python
python_values = x.tolist()
raw_fp16_bits = x.bits()
numpy_values = x.numpy()     # 应用环境需安装 NumPy
single_value = scalar_tensor.item()
```

### 5.5 生命周期

Tensor 在以下情况释放内部 SRAM：

- 显式调用 `tensor.release()`；
- Python handle 被回收；
- `Device.close()`；
- 退出 `with dexsim.Device()`。

释放的 word-aligned 区间进入 free-list，后续同类 Tensor 可以复用。访问已经释放的 Tensor 会抛出 `ReleasedTensorError`。

## 6. 全部高层硬件算子

### 6.1 GEMM/GEMV/DOT/OUTER

```python
C = dev.gemm(A, B)
y = dev.gemv(A, x)
s = dev.dot(x, y)
M = dev.outer(x, y)
```

- `gemm`：rank-2 × rank-2；
- `gemv`：rank-2 × rank-1 或 `(K,1)`；
- `dot`：相同长度 rank-1；
- `outer`：两个 rank-1。

### 6.2 ADD 和 SCALE

```python
z = dev.add(x, y)
w = dev.scale(z, 0.5)
```

`mul` 是 `scale` 的别名。标量会先量化为 FP16 bits，再进入硬件 command。

### 6.3 ABS、Sin、Cos、Softplus

```python
abs_x = dev.abs(x)
sin_x = dev.sin(x)
cos_x = dev.cos(x)
sp_x = dev.softplus(x)
```

Trig 和 Softplus LUT 由 Session 首次使用时自动加载，调用者不需要初始化。

复合操作：

```python
sp_beta = dev.softplus_beta(x, 100.0)
```

内部明确展开为：

```text
SCALE(x, 100)
-> SOFTPLUS
-> SCALE(result, 0.01)
```

### 6.4 Transpose 和 Assemble

```python
AT = dev.transpose(A)
B = dev.assemble(A, offset_row=1, offset_col=2)
```

当前 ASSEMBLE 的目标 shape 遵循 RTL：

```text
(src_rows + offset_row, src_cols + offset_col)
```

v0.3 高层 API 会把新目标 Tensor 初始化为 FP16 `+0`，再执行硬件 ASSEMBLE，因此结果不依赖旧 SRAM 内容。

### 6.5 Reduce

```python
sum_result = dev.add_reduce(x)
min_result = dev.compare_reduce(x)

print(sum_result.value, sum_result.value_bits)
print(min_result.value, min_result.value_bits, min_result.index)
```

兼容别名为 `reduce_add` 和 `reduce_cmp`。

## 7. Trace 和错误

```python
entries = dev.trace()
dev.clear_trace()
```

每个 trace entry 包含：

- operation；
- 内部输入输出 buffer 描述；
- command ID/opcode/subop/96-bit words；
- cycles；
- read/write bytes；
- LUT setup 成本；
- Reduce result。

普通开发者不需要读取内部地址；trace 中保留这些信息是为了硬件调试和性能分析。

主要异常：

| 异常 | 含义 |
|---|---|
| `ReleasedTensorError` | 使用已经释放或失效的 Tensor |
| `UnsupportedShapeError` | 当前单核 SRAM/command field 无法承载，且 v0.3 尚无已验证 tiling |
| `AllocationError` | 内部 allocator 找不到合法 placement |
| `DexSimError` | Simulator、timeout、illegal command 或完成元数据错误 |
| `ValueError` | 算子 shape、offset 或参数语义错误 |

禁止 silent NumPy fallback。硬件不支持的 shape/op 必须明确报错，由上层决定 host 路径。

## 8. Fixed Operator Program

普通开发和调试可以使用 eager `Device` API。对于固定、重复执行的多算子 kernel，可以显式构建 `Program`：

```python
program = dexsim.Program("affine_softplus")

x = program.input("x", (3,))
A = program.constant("A", [[1.0, 2.0, 3.0], [0.5, -1.0, 2.0]])
b = program.constant("b", [0.25, -0.5])

y = program.gemv(A, x)
z = program.add(y, b)
out = program.softplus_beta(z, 100.0)
program.output(out)

with program.compile() as compiled:
    result = compiled.run(x=[1.0, -2.0, 0.5])
    print(result.outputs)
    print(result.trace.to_dict())
```

Program compile 自动完成：

- shape/dtype 检查；
- 复合算子展开；
- 静态 liveness；
- SRAM placement 和临时地址复用；
- 确定性 command ID 和 command batch；
- 常量一次上传；
- 输出和 Reduce result 关联；
- ExecutionTrace。

同一个 Program 在相同版本和 capability 下产生确定、可复现的地址计划。ASSEMBLE 因目标保留语义会形成安全的 command segment，确保清零不会覆盖较早的 live 输入。

Program 不是“任意 Python 编译器”。软件开发者仍需明确写出 `gemv/add/softplus` 的组成和依赖。

## 9. 软件开发者仍需完成什么

v0.3.0 结束的是底层可安装软件栈的主体开发，不会自动完成算法到算子的数学转换。

从 MPC 算法开发一个硬件 kernel 时，开发者仍需：

1. 选择输入输出边界明确的 kernel；
2. 判断哪些计算允许 FP16；
3. 判断哪些计算必须保留 CPU FP32/FP64；
4. 根据公式列出基本算子；
5. 确定算子顺序和数据依赖；
6. 定义量化和反量化位置；
7. 建立硬件顺序一致的 NumPy FP16 reference；
8. 定义不支持/异常时的显式 fallback；
9. 做 fixture、shadow 和 MuJoCo 闭环验证。

v0.3.0 自动负责：

```text
Tensor上传
FP16打包
SRAM选择和地址
生命周期和复用
96-bit command
LUT初始化
Simulator执行
结果读取
trace和错误归因
```

## 10. Kernel 开发示例

数学公式：

```text
x = Q_inv @ b
t = J @ x
z = -sigma * (t + phi) - damping * t
s = softplus_beta(z, 100)
v = (x + Q_inv @ (J.T @ s)) / h
```

高层 Operator 实现：

```python
def velocity_kernel(dev, q_inv, jac, jac_t, b, phi, sigma, damping, inv_h):
    x = dev.gemv(q_inv, b)
    t = dev.gemv(jac, x)
    t_plus_phi = dev.add(t, phi)
    z0 = dev.scale(t_plus_phi, -sigma)
    z1 = dev.scale(t, -damping)
    z = dev.add(z0, z1)
    s = dev.softplus_beta(z, 100.0)
    contact = dev.gemv(q_inv, dev.gemv(jac_t, s))
    return dev.scale(dev.add(x, contact), inv_h)
```

算子组成和顺序由开发者根据数学公式确认；代码没有任何 SRAM 或 command 参数。

M3 固定 forward builder 继续作为逐 bit golden。v0.3 提供 `HighLevelDexMPCForwardKernel`，用高层 API 实现相同 14-command velocity 路径。

## 11. 当前边界

- 生产高层 runtime 只使用 D2D/core0；
- 不自动分析任意 Python/MPC 源码；
- 不自动判断一段公式能否安全使用 FP16；
- 不执行 KKT factorization、triangular solve、Armijo、Active Set 或 MuJoCo；
- 当前只公开一维/二维非空硬件 Tensor；
- 单次 shape 超过全部单核 SRAM 且没有已验证 tiling 时抛出 `UnsupportedShapeError`；
- 不允许 silent host fallback；
- 多核和更复杂 tiling 必须先通过独立 capability/RTL 验证。

## 13. 版本定位

```text
v0.1  初始 persistent runtime
v0.2  完整单核 primitive/command SDK + M3 fixed forward
v0.3  address-free Tensor/Operator SDK + optional fixed Operator Program
```

从 v0.3.0 开始，M7 及后续 Algorithm 生产路径应优先依赖高层 `Device`/`Program` API。低层 API 继续作为验证接口，不再要求普通 kernel 开发者使用。
