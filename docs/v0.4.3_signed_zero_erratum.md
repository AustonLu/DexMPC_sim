# dexmpc-sim v0.4.3 signed-zero erratum

v0.4.3 is a reference-semantics bugfix release on top of v0.4.2. Public
Operator and Program APIs, DOT policies, residency policies and native RTL are
unchanged.

M7 live Allegro FK validation found a GEMM output where TopChip Verilator
returned `0x0000` while the old software golden returned `0x8000`. The MAC
array accumulates in fixed FP16 order and drains through a final positive-zero
add. Therefore any final signed zero is canonically `+0`; the old GEMM/GEMV
golden modeled the multiply/add loop but omitted the drain.

v0.4.3 changes:

- canonicalize a final GEMM/GEMV zero to `0x0000` in the forward reference;
- update the public operator test reference with the same rule;
- add a real-Verilator GEMM test that first produces a negative subnormal,
  flushes it to `-0`, and confirms the final hardware drain emits `+0`;
- require v0.4.3 or newer from the M7 Algorithm backend.

This correction is bit-visible but numerically zero-error. It prevents false
hardware/reference mismatches and keeps the fast M7 reference aligned with the
cycle-accurate simulator.
