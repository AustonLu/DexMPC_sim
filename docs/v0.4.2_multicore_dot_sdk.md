# dexmpc-sim v0.4.2 多核 DOT SDK

适用版本：`dexmpc-sim 0.4.2`。

## 1. 这次版本增加了什么

DOT 的输出只有一个 FP16 标量，不能像 GEMM/GEMV 那样按输出行切分。v0.4.2 增加了独立的 DOT 调度开关：SDK 沿 K 维切分输入，每个 MAC core 生成一个 FP16 partial sum，再由 core0 使用固定顺序的硬件 Add-Reduce 树合并。

```text
x/y K partitions
    -> core0..3 partial DOT
    -> core0 Add-Reduce (fixed tree)
    -> one FP16 output
```

现有 `Device.dot()` 和 `Program.dot()` 的数学 API 不变；开发者不需要指定 core、SRAM、command 或 partial 地址。

## 2. 安装

```bash
python -m pip install dexmpc_sim-0.4.2-py3-none-linux_x86_64.whl
```

wheel 自带 Verilator runtime、Python SDK 和 LUT；使用者不需要单独准备 RTL 源码。

## 3. 开关和策略

### Eager API

```python
import dexsim

with dexsim.Device(dot_execution_policy="quad") as dev:
    x = dev.tensor([0.25] * 127)
    y = dev.tensor([0.5] * 127)
    result = dev.dot(x, y)
```

### Program API

```python
compiled = program.compile(
    execution_policy="quad",       # GEMM/GEMV/OUTER/SCALE/ADD
    residency_policy="on",         # continuous linear subgraphs
    dot_execution_policy="dual",   # DOT only
)
result = compiled.run(x=input_x, y=input_y)
```

`dot_execution_policy` 的含义：

| 值 | 含义 |
|---|---|
| `single` | 强制单核 DOT，关闭 DOT 多核 |
| `dual` | 请求双核，K 太短或不能按 8 个 FP16 对齐时自动退化 |
| `quad` | 请求四核，K 太短或不能按 8 个 FP16 对齐时自动退化 |
| `auto` | 使用已标定收益 Gate；v0.4.2 production 默认选择单核 |

该开关独立于 `execution_policy`。例如可以让 GEMM 使用四核，同时让 DOT 保持单核：

```python
dexsim.Device(execution_policy="quad", dot_execution_policy="single")
```

## 4. 归约和数值语义

双核 partial 按 `[p0, p1]` 进入 Add-Reduce；四核按 `[(p0+p1), (p2+p3)]` 再合并。硬件会将输入补零到 Reduce 引擎的固定 16-lane 树，输入顺序和树结构都写入 trace。归约不依赖哪个 core 先完成。

K-split 会改变 FP16 加法结合顺序，因此多核 DOT 不承诺与单核 DOT 逐 bit 相同。SDK 保证：

1. 每个 partial 与相同 K partition 的 FP16 reference 逐 bit 一致；
2. 最终值与固定 Add-Reduce 树 reference 逐 bit 一致；
3. `ieee_compliance=0` 的硬件语义保持一致：NaN 按 Infinity 处理，denormal 和下溢按 signed zero 处理；
4. trace 同时记录相对单核 FP16 和 FP64 reference 的误差、ULP 和特殊值结果。

## 5. Trace

Eager `dev.trace()[-1]["parallel"]` 和 Program `ExecutionTrace.commands` 会记录：

- `plan.partitions`：每个 core 的 K 起点和长度；
- `partial_bits`：各 core partial 的 FP16 bits；
- `merge_tree`：固定树和 zero padding 规则；
- `resident_reuse`：从连续 resident producer 直接消费的 partition；
- `transfers`：输入 staging、partial gather 和最终输出提交；
- `metrics.engine_compute_cycles`：各 partial engine active cycle 的关键路径加硬件 merge engine cycle；
- `metrics.scheduled_run_cycles`：包含命令提交/等待的 scheduled-run；
- `metrics.total_cycles`：包含 DOT 内部搬运和归约的完整算子周期；
- `host_ops`：production DOT 必须为空。

## 6. 支持边界

- 单核 command 的 K 字段上限仍为 `4095` 个 FP16；
- K 小于 16 或不能形成足够的 8-element word block 时会退化到较少 core；
- partial 输出必须落在 Local/Temp；SRAM 压力或 Global 输出会记录原因并走真实单核硬件路径；
- host merge 只在 `tools/run_dot_merge_experiments.py` 中作为 reference/候选实验，production 不会静默执行 Python 加法；
- DOT 多核不会改变 GEMM/GEMV/OUTER/SCALE/ADD 的既有策略。

## 7. v0.4.2 验证口径

M6.3 使用 K=`8,16,31,64,127,256,511,1024,2048,4095`，覆盖 single/dual/quad/auto，并单独覆盖奇数尾块、NaN、Inf、signed zero 和 FTZ。报告分开统计：

1. 纯 engine active cycle；
2. 排除 tensor 搬运但包含命令提交的 scheduled-run；
3. 包含 partial staging、gather、Reduce 和输出提交的完整 DOT；
4. 输入上传和输出下载后的 end-to-end。

只有完整 DOT 周期达到 `>=1.05x` 才会将对应 K 范围加入 `auto`；v0.4.2 的实测 Gate 未通过，因此 `auto` 保持单核，显式 `dual/quad` 用于实验和后续硬件互连优化验证。
